L3 — 검증 그래프 (실제 스크립트)

되돌리기 어려운 건 "그래프"로 검증한다

명령 하나로 돈다: graph-verify.sh <대상> "무엇을 검증". Codex가 읽기 전용으로 반박하면, 사람/Claude가 고치고 다시 검증 — 단 최대 2라운드. 검증은 무한히 새 지적을 만들어내므로 상한을 둔다. 무엇을 수용·기각할지는 사람 몫.

왜 상한을 2회로 묶나

검증 모델은 멈추라고 하지 않으면 끝없이 새 지적을 만들어낸다. 그래서 라운드를 2회로 못박고, 넘기면 스크립트가 멈춰 사람에게 넘긴다. 또 하나 — 검증 가능한 주장은 동의하기 전에 직접 실측한다: 실제로 Codex가 "키 충돌 위험"을 지적했지만 이 환경에선 0건이라, 설계는 유지하고 검사 항목으로만 편입했다.

L1·L5 — 컨텍스트와 기억

규칙은 자동으로 주입되고, 기억은 자동으로 쌓인다

이게 "혼자서도 안 무너지는" 핵심이다. 규칙을 외우지 않는다 — 문서가 매 세션 주입된다. 작업 내용을 메모하지 않는다 — 세션이 끝나면 기억이 저절로 미러된다.

작업은 어디로 가나 — 허브 & 스포크

던지면 알아서 제 자리로 간다

여러 프로젝트가 유동적으로 엮여 있어서, "이 항목이 무엇이고 어디로 갈지" 판단하는 층이 하나 필요했다. 그게 hub(관제소)다. 코드는 0줄 — 분류하고 라우팅하고 기록만 한다. 실제 작업은 목적지 프로젝트의 정본 세션에서. 전부 사람 확인, 자동 실행 없음.

research — 콘텐츠를 2축으로 판정

인스타·유튜브·논문에서 본 걸 던지면: 학습 → 검증 → 판단 → 결정. 핵심은 두 축을 독립으로 본다는 것 — 한 축이라도 걸리면 살린다.

roadmap — 진로 준비 7 카테고리

research가 "편입" 판정한 증거·학습거리가 쌓이는 곳. 리드 포지션은 AI Agent / AX 엔지니어, breadth는 보안×AI, 무기는 풀스택 배포.

할일은 Todoist 단일 채널 ADR 0006·0007

개인+진로 할일의 진실원을 Todoist로 일원화. 🧭 진로·취업 프로젝트 안에서 섹션으로 영역 매핑. actionable task(동사·완료조건·기한)는 Todoist, 설명·장기방향·산출물은 문서(roadmap)로 — 두 개의 task manager화를 막는다.

왜 허브는 "코드 0줄"인가

폴더를 물리적으로 통합하자는 안은 Codex·Fable 둘 다 기각했다 — memory가 경로에 묶여 있어 이동하면 기억이 고아가 되고(개명 금지 규칙 위반), "마감 유무"라는 분류 축도 무너진다. 그래서 허브는 폴더를 옮기지 않고 판단만 얹는 얇은 층으로 남겼다. 자동 디스패치도 뺐다 — 오라우팅은 엉뚱한 프로젝트 기억을 오염시키고 되돌리기 어렵다.

왜 이렇게 짰나

체계를 떠받치는 4개의 원칙

① 검증은 다른 벤더로

같은 벤더 모델끼리는 편향을 공유한다. 자기검토는 검증이 아니다. 그래서 되돌리기 어려운 건 Codex(OpenAI)로 "반박"받는다.

② 만들기 전에 실측

"이거 만들까"를 판정하기 전에 성숙한 오픈소스가 이미 하는지 조사. 있으면 순수 재구현은 델타 없음 → 포크+델타로만 자산이 된다.

③ 위험 전환에만 게이트

결제·삭제·외부 발송·게시·권한 변경 — 여기서만 사람 확인. 모든 노드에 승인을 넣으면 흐름만 막힌다. 고위험 지점에만.

④ 경로가 곧 정체성

memory가 폴더 경로에 묶여 있다. 그래서 폴더명은 생성 시 확정, 개명 금지. 세션은 항상 프로젝트 루트에서 — 서브폴더에서 열면 기억이 갈라진다.

한 문장 요약

사람은 무엇을·왜만 정하고 위험 지점에서만 개입한다. 작은 일은 로컬이, 품질은 Claude가, 검증은 Codex가 맡는다. 규칙은 외우지 않고 주입되며, 한 일은 저절로 기억된다 — 그래서 혼자서도 여러 대가 돌아간다.

L4 — 능력 상세

플러그인 번들 10개

플러그인은 "작업 방식"을 묶은 번들이다. 각 번들이 수십 개의 스킬을 담는다. 규칙 문서(domains)는 자동 주입되지만, 형식·기능 스킬은 필요할 때 /스킬명으로 명시 호출한다(일부 superpowers·gstack은 설명에 따라 자동 발동).
